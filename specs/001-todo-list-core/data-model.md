# データモデル: ToDoリスト基本機能

## 1. ToDoアイテム

### フィールド

| フィールド名 | 型 | 必須 | 説明 |
|-------------|----|------|------|
| `id` | `string` | 必須 | 各 ToDo を一意に識別する内部 ID |
| `title` | `string` | 必須 | 画面に表示するタスク名 |
| `completed` | `boolean` | 必須 | 完了済みかどうか |
| `createdAt` | `string` | 必須 | 登録日時の ISO 8601 文字列 |

### 検証ルール

- `title` は前後の空白を除去したうえで空文字を許可しない。
- `title` は極端に長い入力を拒否できるよう、実装では最大文字数を定義する。
- `id` は同一保存領域内で重複してはならない。
- `createdAt` は表示時に `YYYY/MM/DD HH:SS` 形式へ整形できる値でなければならない。

### 状態遷移

- 作成時: `completed = false`
- 完了操作: `false -> true`
- 未完了操作: `true -> false`
- 削除操作: 一覧および保存データから除去する

## 2. 表示フィルタ

### 列挙値

| 値 | 説明 |
|----|------|
| `all` | すべて表示 |
| `active` | 未完了のみ表示 |
| `completed` | 完了済みのみ表示 |

### ルール

- 画面上では現在選択中のフィルタを視覚的に判別できること。
- 保存対象に含める場合、再読み込み後も直前の選択を復元する。

## 3. 保存済みリスト状態

### 保存スキーマ

```json
{
  "version": 1,
  "activeFilter": "all",
  "todos": [
    {
      "id": "todo_001",
      "title": "牛乳を買う",
      "completed": false,
      "createdAt": "2026-05-07T08:15:00.000Z"
    }
  ]
}
```

### ルール

- `version` は保存データ形式の識別子として保持する。
- `todos` の順序は作成順を維持する。
- 保存データが壊れている場合は安全な初期状態へフォールバックする。
- フィルタに一致する要素がない場合も、保存状態自体は破棄しない。

## 4. 派生表示データ

| 項目 | 説明 |
|------|------|
| `formattedCreatedAt` | `createdAt` を `YYYY/MM/DD HH:SS` 形式へ変換した表示用値 |
| `visibleTodos` | 現在の `activeFilter` に一致する ToDo 配列 |
| `remainingCount` | 未完了件数を画面補助情報として表示する場合の算出値 |
